# Кубики меню

Мобильное PWA: по воскресеньям «бросаешь кубики» — приложение случайно выбирает блюда на 3/7/14/21 день, строит расписание готовки и список покупок для магазина (Пятёрочка/Чижик) или заказа с доставкой. Один пользователь, без сервера, аккаунтов, аналитики и внешних зависимостей. Работает офлайн, ставится на главный экран.

## Что умеет

**Генератор**
- Горизонт 3/7/14/21 дн., приёмов в день 1/2, порций с варки 2/4, фильтр категорий.
- Квоты типов: суп 30 %, мясное 40 %, рыба 15 %, бобовые 15 %; два супа подряд не ставятся.
- Закрепить ○/●, перебросить ↻, исключить ✕; исключённые лежат в списке и возвращаются по одному.
- «Бюджетный» режим: чаще выпадают дешёвые блюда (поле `cost`, ₽ за 4 порции); сумма плана показана всегда. Цены — мои приблизительные оценки для Пятёрочки, поправьте в `data.js`.
- Кнопка «Завтраки и заготовки на неделю»: 1 завтрак + 2 заготовки + 1 хлеб из рецептов 23–31 дока.
- История: последние 6 планов с датой — открыть / копия / удалить.
- Карточка блюда раскрывается в ингредиенты (на выбранное число порций) и 3–6 коротких шагов.

**Покупки** (mobile-first, 360–430 px, одной рукой)
- Строки от 56 px, тап по всей строке отмечает; отмеченные зачёркиваются и уходят вниз секции; sticky-счётчик «Куплено 12/31» и прогресс-бар.
- Секции в порядке обхода магазина (Овощи → Мясо и рыба → Молочка и яйца → Крупы → Консервы → Специи), порядок меняется стрелками в «Настройках».
- «Есть дома»: долгий тап по строке или кнопка 🏠 переносит позицию в кладовую; кладовая скрыта, учитывается во всех будущих планах, позиции можно вернуть.
- Свои позиции (название + количество) добавляются в конец списка.
- Переключатель «Граммы / Упаковки»: «нужно 350 г → 1 уп. (400 г)». Таблица упаковок — `PACKS` в `data.js`.
- «Поделиться» — `navigator.share`, иначе буфер обмена, иначе запасное окно с текстом. Формат: секции и строки `- название — кол-во`. В текст попадают только ещё не купленные позиции.
- «Заказ с доставкой» — тот же список компактно, одной кнопкой: `Овощи и зелень: свёкла 250 г, …`.
- Экран не гаснет на вкладке «Покупки» (Wake Lock; где не поддерживается — молча игнорируется).
- Отметки переживают перезапуск; сбрасываются только кнопкой «Сбросить отметки» или новым броском.

**Общее:** светлая/тёмная тема по системе + ручной переключатель; экспорт/импорт всех данных в JSON; версия схемы данных и миграция (данные прототипа `menu-dice-v1` подхватываются).

## Как обновлять рецепты

1. Правьте `data.js`: массив `RAW` (шаблон нового рецепта — в комментарии внизу файла). Один и тот же продукт должен называться одинаково и иметь одну единицу, иначе агрегатор не сложит позиции (тест это проверяет).
2. **Поднимите версию кэша в `sw.js`** (`kubiki-menu-v1` → `kubiki-menu-v2`), иначе телефон продолжит открывать старую копию из кэша.
3. Запустите `node tests/aggregate.test.js`, закоммитьте и запушьте — Pages обновится сам. На телефоне приложение обновится при следующем открытии (иногда после второго запуска).

## Деплой на телефон (3 шага)

1. **Создать репозиторий** на GitHub и запушить. Pages на бесплатном плане работает только с публичными репозиториями; в репозитории нет личных данных — они хранятся только на устройстве.
   ```bash
   git remote add origin https://github.com/<логин>/<репозиторий>.git
   git push -u origin main
   ```
2. **Включить Pages:** Settings → Pages → Source: **GitHub Actions**. Первый запуск workflow даст адрес вида `https://<логин>.github.io/<репозиторий>/`.
3. **Открыть адрес на телефоне и добавить на экран «Домой»:**
   - **iOS (Safari):** кнопка «Поделиться» → «На экран „Домой“» → «Добавить». Открывать именно в Safari, не во встроенном браузере мессенджера.
   - **Android (Chrome):** меню ⋮ → «Установить приложение» (или «Добавить на главный экран»).

   Откройте приложение один раз с интернетом — после этого оно работает офлайн.

## Бэкап

«Настройки» → «Экспорт в JSON» сохраняет файл со всем состоянием (план, отметки, кладовая, история, настройки). «Импорт из JSON» восстанавливает его на этом или другом устройстве. Данные лежат в `localStorage` браузера: очистка данных сайта (а в iOS Safari ещё и долгое неиспользование) их стирает — делайте экспорт время от времени.

## Проверки

```bash
node tests/aggregate.test.js        # юнит-тест (без зависимостей)
npm install && node tests/e2e.mjs   # e2e на Playwright (Chromium), скриншоты в tests/out/
```
Локально приложение открывается и двойным кликом по `index.html` (file://); service worker при этом не работает — он нужен только по http(s). Если Chromium из Playwright недоступен, `tests/browser.mjs` берёт установленный Chrome или Edge.

## Принятые решения и допущения

- **Классические скрипты вместо ES-модулей.** Chrome не загружает `<script type="module">` по `file://`, а требование «открывается по file:// и по https» важнее. `data.js` и `logic.js` — UMD-обёртки, поэтому те же файлы подключаются в Node-тесте.
- **Рецепты 23–31** прочитаны из дока (доступ был). Типы: 23 (хумус), 27–29 — `prep` (заготовки/хруст); 24–26 — `breakfast`; 30–31 — `bread`. Они не участвуют в обеде/ужине. Их `qty` — на весь рецепт целиком (не на 4 порции), порциями не масштабируются; в списке покупок умножаются на число недель горизонта (14 дн. → ×2). Где в доке нет количества (корица, ваниль, лавр и т. п.) — «по вкусу», количество не выдумывалось. «Лук ½» записан как 50 г.
- **Рецепты 1–22 взяты из прототипа**, а не из дока: состав в доке местами отличается (например, борщ, щи). Шаги (`steps`) для них составлены по обычной технологии и опираются на описания «Как» в доке.
- **Нормализация названий:** «куриное филе» → `грудка куриная`, «томаты в собственном соку» → `томаты в с.с.`, масло везде в ч.л. (ст.л. → ×3), уксус в мл (1 ст.л. = 15 мл), чеснок «головка» → 10 зубч. — иначе позиции разных единиц не складывались бы.
- **Гарнир** (рис/греча/макароны, ~75 г сухой на порцию) — отдельная строка списка, как в прототипе.
- **Цены (`cost`) и упаковки (`PACKS`)** — мои оценки, не прайс магазина. Для позиций без записи в `PACKS` показываются точные граммы даже в режиме «Упаковки».
- **Кладовая** изначально пуста (соль, масло и специи в рецептах не выделены как «всегда дома»); пополняется вашими действиями. Она хранит названия продуктов, поэтому «лук» убирается из любых будущих планов.
- Смена горизонта/приёмов/порций сразу перегенерирует незакреплённые блюда; новый бросок сбрасывает отметки, переброс одного блюда — нет (по ТЗ).
- Нижняя вкладка называется «Меню» (на 360 px «Меню и готовка» не помещается в три кнопки).
